## Background

`v1.6.2` is a patch release on the `v1.6.x` line. It replaces `v1.6.1` (see the [v1.6.1 release note](./2026-11-v1.6.1.md)) as the binary to deploy on the `v1.6.x` line. The changes since `v1.6.1` are listed in the changelog above.

### Upgrade plan name

The plan name depends on what the network already ran:

- **Networks that already ran the `v1.6` upgrade on `v1.6.1`** (devnet-amplifier, testnet) upgrade with the plan **`v1.6.2`**. They cannot reuse `v1.6`: x/upgrade refuses to schedule a plan whose name was already applied (`upgrade with name v1.6 has already been completed`). Devnet-amplifier applied `v1.6` at height 31928475 with `v1.6.1`.
- **Networks still on `v1.5.x`** (mainnet) upgrade straight to `v1.6.2` with the plan **`v1.6`**, as described in the [v1.6.1 release note](./2026-11-v1.6.1.md), with the `v1.6.2` binaries in place of the `v1.6.1` ones. They never schedule `v1.6.2`.

`v1.6.2` registers a handler for the plan `v1.6.2` ([#2455](https://github.com/axelarnetwork/axelar-core/pull/2455), private #125). It has no store changes and runs the default handler: no module changes its consensus version between `v1.6.1` and `v1.6.2`, so no migration runs and no parameter changes. The `v1.6` handler is unchanged and still runs on networks that upgrade from `v1.5.x`.

Once a network has applied `v1.6.2`, `v1.6.1` refuses to start on it (`upgrade handler is missing for v1.6.2 upgrade plan`).

## Migrate CosmWasm Contracts

No Amplifier contract migrations are required for this upgrade.

## Deployment Steps for Axelar Maintainers

### Proposal file (`v1.6.1` networks)

The upgrade is submitted with `axelard tx gov submit-proposal` and a proposal file that sets `"expedited": true`. `authority` is the gov module account, which has the same address on every network. `info` is the cosmovisor upgrade info with the S3 checksums:

```json
{
  "messages": [
    {
      "@type": "/cosmos.upgrade.v1beta1.MsgSoftwareUpgrade",
      "authority": "axelar10d07y265gmmuvt4z0w9aw880jnsr700j7v9daj",
      "plan": {
        "name": "v1.6.2",
        "height": "<UPGRADE_HEIGHT>",
        "info": "{\"binaries\":{\"linux/amd64\":\"https://axelar-releases.s3.us-east-2.amazonaws.com/axelard/v1.6.2/axelard-linux-amd64-v1.6.2.zip?checksum=sha256:8d549973c64d98fddcf4b562004165e731ccd6452647440421c6ec7c8f2b110f\",\"darwin/amd64\":\"https://axelar-releases.s3.us-east-2.amazonaws.com/axelard/v1.6.2/axelard-darwin-amd64-v1.6.2.zip?checksum=sha256:d150e839386485b248ab6fed8f68d01c90eae57b86849c808b9a085f6f0d6c83\",\"darwin/arm64\":\"https://axelar-releases.s3.us-east-2.amazonaws.com/axelard/v1.6.2/axelard-darwin-arm64-v1.6.2.zip?checksum=sha256:ddab1afaad53b2308b91260ee67ed36c19ab78531714b998cfb7ce74b631a10b\"}}"
      }
    }
  ],
  "metadata": "",
  "deposit": "<EXPEDITED_DEPOSIT>",
  "title": "Axelar v1.6.2 Upgrade Proposal",
  "summary": "This proposal is intended to upgrade axelar-core to v1.6.2",
  "expedited": true

```

The expedited deposits, voting periods and lead times per network are in the network overview of the [v1.6.1 release note](./2026-11-v1.6.1.md).

1. Save the proposal as `upgrade-v1.6.2.json`, submit it from the `devnet-proposer` key, and vote yes from every validator pod:

    ```json
    {
      "messages": [
        {
          "@type": "/cosmos.upgrade.v1beta1.MsgSoftwareUpgrade",
          "authority": "axelar10d07y265gmmuvt4z0w9aw880jnsr700j7v9daj",
          "plan": {
            "name": "v1.6.2",
            "height": "33078757",
            "info": "{\"binaries\":{\"linux/amd64\":\"https://axelar-releases.s3.us-east-2.amazonaws.com/axelard/v1.6.2/axelard-linux-amd64-v1.6.2.zip?checksum=sha256:8d549973c64d98fddcf4b562004165e731ccd6452647440421c6ec7c8f2b110f\",\"darwin/amd64\":\"https://axelar-releases.s3.us-east-2.amazonaws.com/axelard/v1.6.2/axelard-darwin-amd64-v1.6.2.zip?checksum=sha256:d150e839386485b248ab6fed8f68d01c90eae57b86849c808b9a085f6f0d6c83\",\"darwin/arm64\":\"https://axelar-releases.s3.us-east-2.amazonaws.com/axelard/v1.6.2/axelard-darwin-arm64-v1.6.2.zip?checksum=sha256:ddab1afaad53b2308b91260ee67ed36c19ab78531714b998cfb7ce74b631a10b\"}}"
          }
        }
      ],
      "metadata": "",
      "deposit": "150000000uamplifier",
      "title": "Axelar v1.6.2 Upgrade Proposal",
      "summary": "This proposal is intended to upgrade axelar-core to v1.6.2",
      "expedited": true
    }
    ```

    ```bash
    axelard tx gov submit-proposal upgrade-v1.6.2.json \
        --chain-id devnet-amplifier \
        --from devnet-proposer --gas auto --gas-adjustment 1.3 \
        --gas-prices 0.00005uamplifier

    axelard tx gov vote $proposalId yes \
        --chain-id devnet-amplifier \
        --from validator --gas 80000 --gas-adjustment 1.4 \
        --gas-prices 0.00005uamplifier
    ```

2. Wait for the 90-second expedited voting period to end and the proposal to pass.
3. At the upgrade height, bump the Helm-managed nodes (`validator-alpha`, `rpc-01`, `archival-node`) to `axelar_core_version = "1.6.2"` in the [infrastructure](https://github.com/axelarnetwork/infrastructure) repo and apply ("Run devnet-amplifier" with `apply=true`). Dispatch the apply after the halt, because a node started on `v1.6.2` before the upgrade height crashes:
    - `infrastructure/devnet/apps/axelar-devnet-amplifier/validator-alpha/terragrunt.hcl`
    - `infrastructure/devnet/apps/axelar-devnet-amplifier/rpc-01/terragrunt.hcl`
    - `infrastructure/devnet/apps/axelar-devnet-amplifier/archival-node/terragrunt.hcl`
4. Bump the hand-managed StatefulSets in the same namespace (`validator`, `rogue-validator`, `genesis`, `node`, `seed`, `sentry`), which the infrastructure repo does not cover:

    ```bash
    sk aws upgrade devnet-amplifier 1.6.2
    ```

    This sets the image of the six StatefulSets to `axelarnet/axelar-core:v1.6.2` with `kubectl set image`. Blocks resume once three of the four `validator` pods (25% each) run `v1.6.2`.

5. No parameter changes are expected: the `v1.6.2` handler runs no migrations.
6. Check the upgrade, then run the devnet e2e:

    ```bash
    axelard query upgrade applied v1.6.2               # returns the upgrade height
    axelard query permission is-paused                 # not paused
    ```

Rollout notes (2026-11-24):

- Proposal 1623 ("Axelar v1.6.2 Upgrade Proposal", expedited) was submitted by `devnet-proposer` at 10:16:50 in block 33078100 and passed at 10:18:20 with all of the voting power voting yes.
- The chain halted at 33078757 at about 10:31:30. The nodes were switched with `sk aws upgrade devnet-amplifier 1.6.2` and the apply of [infrastructure#1578](https://github.com/axelarnetwork/infrastructure/pull/1578).
- Blocks resumed at 10:35:50 (33078758) with three of the four validators. `validator-0` signs again from 10:37:15.
- After the upgrade: `upgrade applied v1.6.2` = 33078757, and the nodes report version `1.6.2`.
